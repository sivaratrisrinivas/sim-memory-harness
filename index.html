Replay and eval harness · independent project, not affiliated with Sim

What does Sim's memory setting still send to the model?

Sim's windowing code has unit tests. A slip in how the final request is put together would not show up in them. This harness replays 120 made-up conversations through Sim's real windowing and budget code, then checks the assembled request with plain code: are the facts still there, is the order right, is the system prompt kept, is the request about the right conversation.

Nothing here claims a bug in Sim. Dropping old messages is how these settings are designed to work. The point is to make it visible, and to catch a change that breaks it by accident.

What is real and what is faked

Real

  • Sim's history-window.ts, context-policy.ts, context-tokens.ts, constants.ts, copied unchanged from commit 8df65ad (Apache-2.0).
  • Defaults: 10 messages, 4,000 tokens, 16,000 token history budget, 90% context use.
  • The checker is plain code. There is no LLM judge anywhere.

Faked

  • Token counts: characters divided by 4. Sim uses a model tokenizer (and counts long text by bytes, which is real here).
  • Model limits: a fixed 32,000 token window, plus made-up reserves (600 fixed, 4,096 output).
  • No live model. "Facts kept" means the exact text is in the request, not that an agent answered right.
  • Summary mode is not built. Sim's optional auto-summary needs an LLM call.
  • Store and groups: an in-memory stand-in, not Sim's database.
  • Conversations are synthetic. Bulk sizes (tool results 1.2k to 20k chars, pastes 3k to 9k chars) are my choice and drive the shape numbers.

Results by setting

120 cases: 72 dev, 48 held out. The split was frozen before any scoring. Counts shown, not just percentages. No setting was tuned on dev.

Limits

  • Exact text in the request is a proxy for the agent answering correctly.
  • Adapters in Sim also budget schemas, files and output; real windows are tighter than this model.
  • The "isolation" check passes here because the stand-in store looks conversations up by exact id. It is there so a real store adapter or a bad change would be caught. See the injected prefix-leak row.
  • 120 cases is small. Held-out is 48, so differences of a few points are noise.
